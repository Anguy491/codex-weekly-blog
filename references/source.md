# Source computer: weekly handoff

1. Determine the current ISO week in `Asia/Shanghai`. Record the exact `[Monday 00:00, run time)` interval. A rerun for the same week uses a newer revision timestamp.
2. Inventory this week's conversations across local projects before choosing topics. Use app thread tools where available, paginate through the relevant date range, and check archived sessions separately. Local `~/.codex/sessions` and `~/.codex/archived_sessions` (or their equivalents under `CODEX_HOME`) are fallbacks. Verify which locations exist. Select by message timestamp and read the relevant user and assistant turns to establish context and actual outcomes.
3. Group related threads by project. Give the most space to substantive progress, the user's reasoning and corrections, design discussions, algorithm choices, implementation and evaluation, and unresolved decisions. For each important development, record the problem and constraints, the approaches considered, the choice and its rationale, and what the conversation shows was implemented, tested, proposed, or left open. Keep useful technical mechanics and non-sensitive results. Drop tool dumps and routine environment setup, disk cleanup, and similar maintenance unless they explain a project outcome.
4. Apply the detail-level privacy filter in SKILL.md and write the Markdown using note-format.md. Before sending, compare the draft with the project inventory for missing milestones and with the underlying turns for unsupported claims. Check that a reader can follow what changed and why after redaction. Keep drafts outside public repositories. On rerun, preserve the old draft under a revision-specific local filename before replacing it, and use the canonical filename for the new handoff.
5. Use the connected Gmail plugin to send the Markdown file as an attachment to the authenticated account (`to: me`). Subject: `[CodexBlog][YYYY-Www][work] <UTC revision timestamp>`. Include interval and filename in the body. If local file attachment is unavailable, send the complete Markdown as a plain-text body with the same subject and a `Filename:` line. Do not send material that still requires privacy review.
6. Confirm the send result. On failure, retain the local draft and report the error. Do not claim delivery from an attempted send.
